NORINA | المرحلة 2C – إنشاء الطلب مع تسعير توصيل يدوي

ما الذي تغير؟
- أصبح زر إتمام الطلب يفتح نموذج بيانات العميل والعنوان.
- يشترط تسجيل الدخول قبل إنشاء الطلب.
- يُنشأ الطلب في Supabase عبر دالة آمنة تعيد حساب أسعار المنتجات من قاعدة البيانات.
- يُحفظ الطلب بحالة pending_delivery_quote، وتبقى رسوم التوصيل والإجمالي النهائي غير محددين (NULL) إلى أن تتواصل نورينا مع العميل وتحدد رسوم Yango.
- بعد نجاح الحفظ، يفتح WhatsApp برسالة تحتوي رقم الطلب وتفاصيل التنسيق.
- لا يتم تحصيل مبلغ أو اعتماد دفعة عند إنشاء الطلب.

خطوات التثبيت:
1) في Supabase افتح SQL Editor.
2) نفّذ الملف: NORINA-phase2C-order-rpc/02-secure-order-creation.sql
3) يجب أن تظهر رسالة نجاح. إذا ظهر أي خطأ، توقف وأرسل صورة الخطأ قبل المتابعة.
4) فك ضغط الحزمة كاملة، واستبدل مجلد norina-store السابق بالمجلد الموجود في هذه الحزمة.
5) شغّل الموقع عبر خادم يدعم JavaScript modules (مثل VS Code Web مع خادم مناسب).
6) اختبر بحساب عميل: أضف منتجاً، سجّل الدخول، أدخل بيانات توصيل اختبارية، ثم أرسل الطلب.
7) تحقق في Supabase > Table Editor من ظهور سجل في orders بحالة pending_delivery_quote، وأن delivery_fee_omr و total_omr فارغان، ومن وجود تفاصيل المنتجات في order_items.

مهم:
- لا تنفذ ملف SQL القديم الموجود في حزمة Phase 2C السابقة؛ استخدم الملف الموجود داخل هذه الحزمة فقط.
- لا ترفع إيصال تحويل في هذه المرحلة. مسار الإيصالات يحتاج اختباراً مستقلاً لسياسات Storage.
- لا تعتبر الطلب مؤكداً لمجرد حفظه. يجب الاتفاق مع العميل على رسوم التوصيل والإجمالي أولاً.
- لا تشارك كلمات المرور أو مفاتيح Supabase السرية. المفتاح العام Publishable فقط مسموح في الواجهة.
